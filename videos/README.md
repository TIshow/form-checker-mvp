# videos — 解析にかける元動画

**中身は git に入りません**（`.gitignore` の `*.mp4` / `*.mov`）。
置き場所を決めておくだけのディレクトリで、ファイルは各自の手元にある。

```
videos/
  tennis/     サーブ
  baseball/   投球
  golf/       スイング
  opera/      発声姿勢
```

## 入れる前に確認すること

解析にかける前に必ず通す。ここを飛ばすと、**エラーも出さずに
それらしい間違った数字**が出る。

```bash
python tools/videoinfo.py videos/baseball/xxx.mp4    # 実fps・解像度・尺
python tools/camera_motion.py videos/baseball/xxx.mp4 # カメラが動いていないか
```

| 確認 | なぜ |
|---|---|
| **実fps** | 時間に関わる指標が倍率ごとずれる。スロー撮影は申告と実撮影が違う（`tools/estimate_fps.py`） |
| **カメラが静止しているか** | 動くと世界座標が壊れる（[008](../docs/issues/008-moving-camera-slam.md)）。三脚に統一している |
| **動作だけに切り詰めてあるか** | 長いまま投げると前後の立ち姿のノイズで**本体まで壊れる**（実例: 10.9秒のうちサーブ3秒を全長で投げたら利き手判定まで反転した） |
| **回転フラグ** | iPhone 縦撮りは無言で90°回る（`backend/reconstruct.py` 未修正） |

## 競技ごとに必要な撮影条件

| | 最低fps | 理由 |
|---|---|---|
| テニス サーブ | 60 | 体節間の時間差 20〜40ms |
| ゴルフ | 60 | 同上 |
| **野球 投球** | **240（見積もり・未検証）** | 内旋 約7,000°/秒。接地→リリースが 120〜150ms しかない |
| 野球 打撃 | 120（見積もり・未検証） | 骨盤→肩→手の時間差は数十ms |
| オペラ | 不問 | 持続的な状態を測る |

iPhone のスローモーションは 240fps で撮れる。ただし**コンテナ上の fps が
30 と書かれていて実撮影が 240** のことがあるので、`tools/estimate_fps.py`
で確かめること。

## 第三者の映像について

放送映像や他人のプレー動画は、技術評価には使えても**再配布や営業デモには
使えない**。手法の比較や不具合の切り分けに留め、外に出す素材は自分で
撮影したものか、許諾を取ったものにすること。
