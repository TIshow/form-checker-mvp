# Issue 010: 結果を測る（ボール速度・コース・ポイント）

Status: Open
作成: 2026-08-09

## なぜ必要か

「フォームを直したらスピードがどれくらい変わるか」「このサーブならキープ率は
どれくらいか」といった問いが出た。調べたところ、**どれも同じ場所で詰まる**。

**姿勢解析は「どう動いたか」しか教えない。性能に繋ぐには「何が起きたか」が要る。**

いま持っているのは関節の動きだけで、ボールがどこへ何km/hで飛んだか、その
ポイントを取れたかを一切記録していない。これは姿勢解析の精度の問題ではなく、
**測っていないものは推定できない**という構造の問題。

だから本 issue は姿勢解析の拡張ではなく、**別系統のデータ収集**として設計する。

## 何が開くか

| 問い | 必要なもの | 現状 |
|---|---|---|
| 相対的な速さの比較（前回比） | 姿勢のみ | **すでに可能**（角速度） |
| 絶対的なパワー[W] | 加速度の精度 | **不可**（下記） |
| 「膝を深くすると速い傾向」 | ボール速度 + 自分の複数本 | ボール速度が要る |
| 「10°深くすれば +5km/h」 | 介入実験 or 交絡処理 | **言えない**（因果の主張） |
| サーブゲームのキープ率 | ポイント獲得率 p | p の記録が要る |

## 段階

### 1. ボール速度

「フォーム → 速度」の相関を、**同一人物内で**作れるようになる。体格や技術
レベルという交絡が効かないので、集団の相関より遥かに defensible。

- 「あなたの過去50本では、膝が深いときほど速い傾向」→ **言える**
- 「10°深くすれば +5km/h 速くなる」→ **言えない**（反実仮想。介入実験が要る）

この線引きは [analysis/feedback.py](../../analysis/feedback.py) の Tier A/B/C
（閾値の出典管理）と同じ姿勢。根拠の強さを偽らない。

**手段の候補**:

| | 利点 | 欠点 |
|---|---|---|
| 市販のスピードガン | 精度が確実、導入が即日、安価 | 人が構える手間 |
| 映像からのボール追跡 | 追加機材なし、コースも同時に取れる | 120fps以上が要る。実装コスト |

部活動向けなら**スピードガンの方が現実的**かもしれない。映像追跡は
[006](006-racket-tracking.md) のラケット追跡と技術的に隣接するので、
やるなら一緒に検討する。

### 2. コース（着弾位置）

サーブの評価は速度だけでは決まらない。ワイド/センター/ボディの打ち分けと、
サービスボックスのどこに入ったか。映像追跡なら速度と同時に取れる。

### 3. ポイント結果

イン/アウト、フォルト、そのポイントを取れたか。**これは人が記録するのが
確実で安上がり**。スコアアプリで足りる。映像から自動判定する必要はない。

### 4. キープ率の計算

ここまで揃えば、[O'Malley (2008)](https://doi.org/10.2202/1559-0410.1100)
の式でゲーム・セット・マッチの勝率が出る。テニスは「ポイント→ゲーム→セット」
の入れ子構造なので、1ポイントを取る確率 p から上位の確率が閉じた式で導ける。
2007年ウィンブルドンの実データで検証されている。前提は「各ポイントが独立同分布」。
実際には勢いや疲労で独立ではないので近似だが、論文自身がその妥当性を検証している。

## 注意: 4段目は簡単で、我々のデータを使わない

**p さえあれば式に入れるだけ**で、実装は数十行。そして **p は姿勢解析なしで
得られる**（100ポイント サーブして勝った数を数える）。

つまり「勝率を出す」という機能単体は、**これまで作ってきた3D解析を一切使わない。**

我々のデータに意味が出るのは「**姿勢 → p**」を予測できたときだけ。
そこを目指さないなら、勝率表示は見た目が派手なだけの飾りになる。

## 絶対的なパワー[W] は出せない（測定済み）

逆動力学には加速度、つまり**2階微分**が要る。復元された軌跡は平滑化されており、
同じクリップの同じ重心から、解析窓を変えるだけでこれだけ振れる:

| 解析窓 | 見かけの重力 | 真値との比 |
|---|---|---|
| 重心ピーク ±6フレーム | 10.49 m/s² | 1.07倍 |
| 重心ピーク ±20フレーム | 2.89 m/s² | **0.29倍** |

（[tools/estimate_fps.py](../../tools/estimate_fps.py) に記録した実測値）

**3.6倍の幅がある。** ワット数を表示したら実質フィクションになる。
地面反力もフォースプレート無しでは推定の域を出ない。

**相対比較（前回比・左右差）は今のデータで可能**なので、そちらに寄せる。

## 進め方

1. **ボール速度から。** 一番レバレッジが高い。相関の提示と、キープ率への道を
   同時に開く
2. スピードガンで始めて、映像追跡は必要になってから。機材で解ける問題に
   実装コストを払わない
3. ポイント結果は人が記録する前提で設計する

## 受け入れ条件

- 1本のサーブに対して「フォームの指標」と「ボール速度」が紐づいて残る
- 「あなたの中で速い/遅い」が、根拠のある形で言える
- 因果を主張しない。相関は相関として提示する

## スコープ外

- ラリーまで含めた試合シミュレーション（相手依存で、姿勢解析の射程外）
- 絶対的な力・パワーの提示
- 映像からのイン/アウト自動判定（人が記録すれば足りる）
