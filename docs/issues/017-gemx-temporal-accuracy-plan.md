# GEM-Xの時系列精度：DDIM経路の検証と比較計画

Status: 第一実験 実施済み（DDIM は実際に走り、手・膝・足で改善。採用は保留。下の「実験結果」）
2026-09-21。実行版: `3299255`。

## 方針

GEM-Xを動画の主推定器として評価を続ける。現在のregression経路も系列入力を
処理しており、DDIMへの切替は「単一画像→時系列」ではなく、推論方法の切替。
色順修正済みの入力を固定して比較し、不採用の再投影補正は再利用しない。

現在の `output_golf_gemx_rgb/provenance.json` は同じ動画SHA・固定版・RGB修正を記録。
NPYで再確認した手首間隔はf109: 33.0→21.4cm、f140: 77.7→71.4cm。
トップ付近は改善したが、フィニッシュは未解決。手首間隔は正解の3D誤差ではない。

## DDIMを試す前に確認すべき固定版の不整合

公式docs/DEMO.mdの `--ddim`（50steps）は `demo_soma_onnx.py` の引数。
現在のバックエンドが使う `demo_soma.py` の引数には無い。

さらに、固定版のONNXデモのPyTorch/DDIM経路は:

```python
model.pipeline.regression_only = False
```

を設定するが、`Pipeline.forward` が呼ぶ `GEMDiffusion.forward_test` の分岐は:

```python
if self.regression_only:
    # zero-input single-pass regression
else:
    # diffusion.ddim_sample_loop_with_aux(...)
```

ここでのselfは `model.pipeline.denoiser3d`。
`configs/exp/gem_soma_regression.yaml` は
`network.model_cfg.regression_only: true` を設定する。
Pipelineからこの属性へ設定を伝える処理は読んだ経路に無い。
**静的コード上では、上位のフラグだけでは実際のDDIM分岐へ切り替わらない。**
GPUでの実行確認前なので、DDIMを実施した・精度を改善したとは記録しない。

実装では現在のPyTorch前処理を維持し、ロードしたモデルの実際の分岐先
`model.pipeline.denoiser3d.regression_only` を明示設定する方法を検証する。
有効ステップ数、スケジュール、乱数seed、サンプラ入口への到達、denoiser評価回数を
記録する。CFG等により呼出回数が増えるため「関数がちょうど50回」だけで判定しない。
回帰経路に戻った場合は停止し、DDIMという結果名で保存しない。

## 第一実験：推論方法と既存後処理を分ける

同じ映像フレーム、RGB修正済み2D、bbox、SAM特徴、K、重み、座標変換を固定する。
ONNXへ全面移行すると前処理や数値精度まで変わるため、この比較では全経路PyTorch。
画像特徴は維持し、`--no-imgfeat` を同時に試さない。

| 実験 | 推論 | GEM-X既存の接地後処理 | 目的 |
|---|---|---|---|
| A | regression | off | モデルの出力そのもの |
| B | 真に有効なDDIM 50steps | off | DDIMの効果 |
| C | regression | on | 現行相当・既存後処理の効果 |
| D | 真に有効なDDIM 50steps | on | DDIMと既存後処理の組合せ |

全条件でアプリ側の足固定や不採用の姿勢補正を適用しない。
まず固定seedで比較。DDIMが有望なら事前に決めた追加seedでも不安定性を確認し、
最も見栄えのよい結果だけを選ばない。処理時間も前処理/推論/描画に分けて記録する。

## 既存処理との重複を避ける

- bboxは現行公式デモで既に5フレーム平滑化される。追加平滑化より、人物ID、
  手・足の切れ、中心とスケールの急変を先に確認する。強くすると高速動作で追従が遅れる。
- `GEM.predict` は `j2d_visible_mask = kp2d_conf > 0.5` を作る。
  ただし0.5以下の情報が全経路で完全に無視されることとは同義ではない。
  後段の条件マスクと生のobsがどこへ渡るかを確認して変更する。
- スコアは較正された確率ではない。高スコアの誤検出もある。短い人手ラベル、
  可視/不可視、時間的一貫性と合わせる。長い遮蔽を直線補間して観測扱いにしない。
- `gem_pipeline.py` には接地によるtranslation補正とIKがある。
  `postproc=True` かつ必要な出力があるときに実行される。各実験で実際の適用を記録する。
- 体型/骨長を固定する前に既存のidentity/scaleが既に一定か確認する。
  同じ処理を追加するだけでは精度改善にはならない。

## 第二実験以降：残った誤差に限定して対応する

1. 2D誤検出が残る局面は、可視性と少量の確認ラベルを改善してGEM-Xへ再入力。
2. カメラ空間の形が妥当で世界座標の足が崩れる場合、K・床・上方向と既存接地処理を検証。
   表示格子を実測床と扱わず、関節中心を足裏の接触点と扱わない。
3. 後処理が必要ならSOMAの関節回転・rootを変数とし、FKで体型・骨長を保つ。
   再投影は外れ値に強い誤差関数と可視性を使い、奥行きを無制限に動かさない。
4. 速度・加速度・jerkを一律に小さくしない。実撮影の時間間隔で評価し、
   インパクト前後の速度ピーク・タイミング・位相遅れを保つように制約する。
5. 接地は確認できた足裏の区間だけ。踵上げ、つま先を軸にした回転、踏み替えを許す。
   ゴルフでは両手とクラブのグリップ接触も扱う。手首中心を0距離へ寄せない。
6. 長い遮蔽/奥行きが残る場合は同期した別視点で評価し、必要なら撮影条件の変更、
   許諾データによる追加学習、提供指標の限定を検討する。

## 管理画面・採用条件

同一フレームで、元映像、2D（bbox/ID/スコア/可視性）、カメラ内メッシュ、世界座標メッシュを
確認できるようにする。既存クリップ画面のメッシュ/2D表示を活用し、モデル設定と
後処理の有無を表示。世界座標比較は共通の表示変換・床基準とし、各結果の床合わせで
誤差を隠さない。まず入力→カメラ内→世界座標の順に原因を追う。

独立した確認点の2D誤差、参照可能な角度、足部と床、手とクラブ、ピーク速度/時刻、
局面別の破綻数を記録する。再投影誤差や手首間隔だけで採用しない。
1動画でデバッグした後、別人物/別撮影条件を固定の評価セットにする。
3Dの角度精度を標榜するには同期多視点などの独立した参照が必要。

## 実装時の再現性

前処理キャッシュは動画SHA・回転/リサイズ・bbox/2D設定・色順・モデル版で識別。
推論結果はさらにsampler・steps・seed・カメラモード・既存後処理の有無で識別する。
コンテナ再利用時の色順パッチは、繰り返し適用やA/B切替でも確実に同じ状態にする。
現在の1回だけの文字列置換は、連続実験の前に修正が必要。

## 実験結果：A〜D を同じ入力で実行した（2026-09-21、Claude）

実行: `backend/gemx_experiments.py`（1 コンテナで前処理 1 回 → 5 条件の推論 →
3 条件のメッシュ描画）。出力 `output_golf_gemx_exp/<条件>/`、`report.json` に
各条件の分岐・denoiser 評価回数・後処理の適用・所要時間。
確認画面: `web/clip.html?clip=golf_gemx_ddim`（D のメッシュと A のメッシュを並べる）。

**上の静的分析は正しかった。** `pipeline.regression_only` を書いても分岐は変わらず、
`pipeline.denoiser3d.regression_only = False` を直接書いてはじめて DDIM に入った。
denoiser の評価回数: regression 1 回、DDIM 100 回（50 steps × CFG サンプラの 2 回）。
`static_conf_logits` は全条件で出ていて、後処理は `postproc=True` の条件でだけ走った
（`infer_version` 2）。推論時間は regression 0.4 秒、DDIM 3.0 秒（172 フレーム、L4）。

seed 0 と 1 の差は平均 0.1cm・最大 0.7cm（`ddim_eta 0`、CFG scale 1.0 なので
初期ノイズしか効かず、その影響もほぼ無い）。A と B の差は平均 3.8cm・最大 18cm。
A と C の差は平均 108cm——GEM-X の接地後処理はほぼ**全体の並進**を動かしていて
（滑り 1.51→0.65m）、姿勢は 1° 程度しか変えない。

**分かったこと**

1. **DDIM は走り、手・膝・足の高さ差で揃って改善した。** regression モードで
   学習した重みでも、途中のタイムステップを通す方が出力が良い。
   ただしフィニッシュの遮蔽（61〜67cm）は DDIM でも解けない。
2. **代償が二つ。** 手の最高速度が 6.1→5.7 m/s（−7%、時刻は不変）。
   前傾がアドレスで 17.0→12.1°（GVHMR 15.5 を挟んで反対側に外れる）。
   どちらも「奥行き・速さを均す」方向で、上の §「第二実験以降」4. の懸念どおり。
3. **既存の接地後処理は残す。** 姿勢を壊さず滑りを半分にする。ただし残り 55cm は
   後処理では消えない（アプリ側は表示だけ足を留める方針のまま）。
4. **局面検出の穴を DDIM が露わにした。** 切り返しで手が一瞬止まるので、
   「トップまでで最後に遅かった枚」がトップ自身になり、テイクバックが f0 に
   飛んだ。regression 出力は閾値を 0.05 m/s 上回っていただけ。遡る起点を
   バックスイング中の速さの頂点に変えて修正（`domains/golf_swing.py`、テスト追加）。
   修正後は全条件で 80〜81（GVHMR 81）。
5. **GPU の前処理は bit 再現しない。** 同じ動画・同じ設定でも ViTPose の 2D は
   全フレームで数 px 動き、スコア 0.4 以下の点は 16 フレームで 50px 超（両峰の
   ヒートマップの argmax が反転する）。3D は平均 0.6cm、最大 8.4cm（f131、遮蔽中）。
   「同じ動画で再実行したら値が変わった」は、この範囲ならバグではない。

**判断**: `backend/reconstruct_gemx.py --ddim` として使えるようにした（既定 off）。
本番経路で走らせた出力（`output_golf_gemx_ddim/`、provenance に `inference: ddim50`）は
実験の D と平均 0.6cm・最大 5.6cm の差——上の 5. の非決定性の範囲で一致した。
採用は上の「管理画面・採用条件」のとおり、別人物・別条件と独立した 2D 確認点で
決める。1 本の動画で DDIM が勝ったからといって切り替えない。
ゴルフの出荷線（SAM 3D Body を横から）は変わらない。

## 分析：f102〜103 の「飛び」と、GVHMR との差はどこにあるか（2026-09-21、Claude。修正はしていない）

確認画面 `clip=golf_gemx_ddim` で、トップ付近（f102→103）に 3D の飛びと、
メッシュの合いの悪さが指摘された。数字で切り分けた。

**1. f102→103 の飛びは推定ではなく表示側。** 計測用の関節列はこの区間で
1 フレームあたり最大 4.7cm しか動かない（GVHMR は 7cm）。表示用の関節列だけが
f102→103 で **35cm**（左つま先）動く。表示だけの足留め（`pin_feet`）が
f100〜102 で左足を留めた位置に固定しており（推定との差 24→27cm と増加）、
f103 で留めが外れた瞬間に推定位置へ飛んだ。**留めが誤差を 3 フレーム隠して
一度に吐き出した**——上の「管理画面」の「各結果の床合わせで誤差を隠さない」
そのもの。計測値には影響しないが、表示としては誤解を生む。

**2. GVHMR との最大の差は、後ろ足（右）の奥行き。** 胴体（骨盤・股・肩・首）で
剛体合わせしたあとの関節差（cm）:

| 局面 | 全関節平均 | 最大の関節 | 右足首の奥行き差 | 同・画像面の差 |
|---|---:|---|---:|---:|
| アドレス | 8.6 | 左つま先 23 | +12 | 5.6 |
| バックスイング | 11.9 | 右つま先 38 | +32 | 4.1 |
| トップ f108-112 | 12.7 | 右つま先 48 | **+40** | 8.0 |
| ダウン | 13.1 | 右つま先 45 | +39 | 5.9 |
| フィニッシュ | 13.0 | 左手 50 | +5 | 10.3 |

正面撮りなので両足はカメラからほぼ等距離のはず。GVHMR は両足首の奥行き差が
トップで 3cm、GEM-X（DDIM）は **40cm**、SAM 3D Body は 27cm。画像面での
足の位置は 4〜8cm しかずれず、2D 検出の足のスコアは 0.95 以上——**検出の
問題ではなく、ネットワークの奥行き推定**。カメラ視点のメッシュ描画では両者とも
体に重なって見え（画像面は合っている）、3D を斜めから見ると後ろ足だけが
遠くに置かれて見える。ユーザーが見た「3D モデルがずれている」はこれ。

**3. 腕はそれより小さいが、形が違う。** トップで両手首 20cm（GVHMR 16、
SAM 3D Body 10）、右肘が 14° 深く曲がり、肩幅が 33cm（GVHMR 37）と体型自体が
細い。差は画像面 7cm・奥行き 3.5cm で、脚の奥行き（24cm）よりずっと小さい。

**4. 同じ物差しで SAM 3D Body は GVHMR に近い。** 胴体合わせ後の平均差は
6〜8cm（GEM-X 9〜13cm）。奥行きの弱さは SAM 3D Body にもあるが、脚では
GEM-X の方が大きい。SAM 3D Body の弱点は前傾（胴体の向き）で、この合わせ方では
消えている。

**含意**: GEM-X の残る誤差は「奥行き」に集中している。2D を良くしても
（色順修正・DDIM で腕は揃った）脚の奥行きは動かない。正面 1 台で解けない
のは SAM 3D Body と同じで、上の「第二実験以降」5.（同期した別視点）に行き着く。
表示の足留めは、留めを外すときに数フレームで戻す（急に飛ばない）か、
留めた量を画面に出すかのどちらかが要る——別 issue で扱う。
