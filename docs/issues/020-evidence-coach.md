# 根拠付きの改善点を生成AIで出す（まずゴルフ）

Status: 実装済み・根拠収集は継続
作成: 2026-09-21

## 何を作ったか

計測値（`clip.json`）と**根拠表**（`domains/golf_swing_evidence.py`）だけを生成AIに渡し、
「ここがこうなので、こう直す」を JSON で書かせて `web/data/<clip>/coach.json` に保存、
`clip.html` が「改善点（生成AI・根拠付き）」として表示する。

    python tools/coach.py --clip golf_gvhmr            # ANTHROPIC_API_KEY が要る
    python tools/coach.py --clip golf_gvhmr --dry-run  # プロンプトを見るだけ

## 根拠が薄いことをどう扱うか

「プロと比べて」は使わない（比較対象が無い）。代わりに「身体の使い方として効率が悪い／
傷害と関係がある」と**文献が言っている範囲**と、**言っていない範囲**を根拠表に書く。

- 改善点と書けるのは Tier A（力学的原理）か Tier B（本文を開いてセクションまで
  確認した文献）に結びつくものだけ。`coach.validate` が根拠 id・tier・指標の一致を
  機械的に照合し、通らない項目は「観察」に降格する
- Tier C（通説、単一研究、未確認の孫引き）は観察として数値を述べるだけ
- 負の根拠（「腰痛と悪い技術の関係は決定的でない」「クランチファクターと腰痛の関係は
  示されていない」）も表に入れる。生成AIが通説で断定するのを止めるため

## 一次資料（本文確認済み）

| | 何に使う |
|---|---|
| Bourgain et al. 2022, Sports 10(6):91（系統的レビュー、92 本） | 連鎖の原理と計測限界、ダウンスイング 0.3 秒、X-factor の典型値と定義差、X-factor stretch、クランチファクター負の根拠 |
| Watson et al. 2024, J Sports Sci 41(24)（腰痛の系統的レビュー、9 本） | 側屈と腰痛（エリート）、リード膝屈曲と腰痛発症（単一研究）、「悪い技術＝腰痛」の否定 |

Edwards et al. 2020（PMC9219256）は自動抽出のみで人手で通読していないので「未確認」。

## golf_gvhmr で出た結果

改善点 1 件（骨盤先行の伸張が見えない。確度 low）、観察 8 件、測れていないもの 5 件。
根拠が薄いところは薄いと出る。これが正しい挙動。

## 続けること

1. **側屈**を測る（G-B4 が腰痛と結びつけている唯一の運動学量。24 関節で取れる）
2. 一次資料を増やす: X-factor stretch の原典（Cheetham 2001）、リード膝の原典
   （Quinn 2022）、Hume 2005（アドレス姿勢・体重移動）。本文を開いて Tier を決め直す
3. 他競技（野球投球・打撃、オペラ）にも同じ形で根拠表を作る
4. API で実行する（今回の golf_gvhmr の coach.json はセッション内で同じプロンプトを
   手動実行したもの。`generated_by` に明記）
5. 結果（クラブヘッド速度・打球）を測って、改善点が結果に効いたかを追う（[010](010-outcome-measurement.md)）

## オペラ（2026-09-21）

`domains/opera_posture_evidence.py` を追加。姿勢と声の論文は有料誌が多く、**本文まで確認できた
ものは無い**（Knight & Austin 2020、Longo et al. 2020 は Europe PMC の抄録のみ）。
だから Tier B が無く、`clip=opera_gvhmr` / `clip=opera` の coach.json は**改善点ゼロ**、
観察 7 件、測れていないもの 6 件。根拠が無いときに欠点を書かない、が守られている。

音声の要約は `audio_` を前置した計測値として生成AIに渡す（`tools/coach.py`）。
Tier を上げるには本文の入手（大学図書館・著者依頼）か、反復測定で自前の根拠を作るか。
