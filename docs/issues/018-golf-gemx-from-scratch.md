# ゴルフ × GEM-X を 0 から積み上げる（上流に手を入れない）

Status: Step 1 完了（素の出力を土台に置いた）
作成: 2026-09-21

## なぜリセットするか

015〜017 で、GEM-X の出力に対して再投影補正・色順パッチ・DDIM 切替・接地後処理の
比較・表示の足留めを重ねた。効いたものも効かなかったものも分かったが、
**どの数字がどの改変の結果なのか**が追いにくくなり、確認画面で見えた「飛び」が
表示側の処理だった（017 末尾）ように、改変そのものが新しい混乱を生み始めた。

だから一度すべて外して、**上流の GEM-X をそのまま走らせた出力**を土台に置き、
一段ずつ「何を足したら何が変わったか」を数字と画面で確かめながら積む。

015〜017 は記録として残す（結論はそのまま参照できる）。コードからは
`core/refinement.py`、`tools/refine_golf.py`、`backend/golf_capture.py`、
`backend/gemx_experiments.py`、`web/golf-review.html`、`reconstruct_gemx.py` の
色順・DDIM パッチを外した（2026-09-21）。出力ディレクトリも削除した。
017 までに分かったことのうち、次に積む候補になり得るもの:

| 分かったこと | 出典 |
|---|---|
| 上流デモは ViTPose に色を逆に渡している（2D の手首がトップで崩れる） | 016 |
| 上流の `--ddim` は効いていない。効かせると手・膝は揃うが速度ピークが 7% 落ちる | 017 |
| 残る最大の誤差は後ろ足の奥行き（+40cm）。2D は合っている。単眼の限界 | 017 末尾 |
| 表示の足留めは誤差を隠して一度に吐き出す | 017 末尾 |
| 再投影で 3D を補正すると画像には合うが 3D は壊れる | 015/016 |

## 進め方

各ステップで「入力・処理・出力・確認画面・数字」を一つずつ固定し、
前のステップとの差分だけを見る。**上流のコードは変えない**（変える必要が
出たら、それは別のステップとして明示する）。

### Step 1: 素の GEM-X（完了 2026-09-21）

- 入力: `videos/golf/golf_form1.mp4`（回転フラグを画素に焼くだけ。切り出しなし）
- 処理: `backend/reconstruct_gemx.py`（公式デモ `demo_soma.py -s` をそのまま。
  公式 SOMA アダプタで関節へ）
- 出力: `output_golf_gemx/`（`gx_joints.npy`、`gx_kp2d.npy`、公式のメッシュ描画、
  `provenance.json` に `upstream_modified: false`）
- 確認画面: `web/clip.html?clip=golf_gemx`（**表示の足留めなし**。`--no-anchor`）
- 数字: `python -m analysis --joints output_golf_gemx/gx_joints.npy --fps 30 --domain golf_swing`

ここで見えるものが「GEM-X の素の実力」。これ以降のステップは全部これとの差分。

**Step 1 の数字**（`upstream_modified: false`、動画 SHA `02b5d6b8…`、172 フレーム）:

| | 値 |
|---|---:|
| 局面 takeaway / top / impact / finish | 79 / 110 / 116 / 127 |
| 両手首の距離 トップ f108 / インパクト f117 / フィニッシュ f132-144 | 34 / 18 / 76〜78 cm |
| 両手首の距離の SD（スイング区間） | 7.3 cm |
| インパクトのリード膝 | 143° |
| 頭の上下動 | 7.2 cm |
| 錨の足の滑り（表示で留めていない生の値） | 0.58 m |

以前の同条件の記録（016 の「旧」列）と同じ水準。トップで両手が離れ、
フィニッシュで腕が崩れ、足は 58cm 滑る——これが土台。
