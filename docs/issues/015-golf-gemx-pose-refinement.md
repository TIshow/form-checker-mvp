# ゴルフのGEM-X精度：同一フレーム診断と改善実験

Status: Rejected experiment（公式経路統一は維持。再投影補正は不採用。[追加診断016](016-golf-refinement-rejection.md)）
調査日: 2026-09-21。モデル再推論・再学習は未実施。

## 結論

GEM-X の前傾角が GVHMR に近いことだけでは採用を決められない。
この素材には生の出力段階で膝・肘・左右の手首間隔の大きな違いがある。
カメラ空間にも同じ関節形状の違いがあるので、床合わせ・全身回転・SLAMだけでは直らない。
改善の優先順位は、公式の骨格復元経路との一致確認 → 2D入力の検証 →
画像再投影と両手グリップを使う姿勢最適化 → 必要ならデータ追加・再学習。
改善する可能性はあるが、GVHMRと同等の精度を保証する設定変更は確認できていない。

## 生データで確認できた差

| 比較箇所 | GVHMR | GEM-X |
|---|---:|---:|
| f22 / 0.73秒 左膝角（180°が伸展） | 155.4° | 179.4° |
| f109 / 3.63秒 左右手首間距離 | 15.5cm | 33.0cm |
| f118 / 3.93秒 右肘角 | 114.4° | 147.6° |
| f150 / 5.00秒 左右手首間距離 | 15.7cm | 57.2cm |

これはモデル間の不一致であり、GVHMRを正解とした真の誤差ではない。
関節中心の定義・体格推定も異なる。手首間距離は握り方や手首姿勢で変動するため、
「必ず10〜15cm」「必ず一定」「0cmが正解」としない。
それでも、両手で同じクラブを保持している目視区間で距離が大きく変動することは、
優先して検証すべき異常の手掛かりになる。最後に手を離した区間を一律拘束しない。

## 切り分け

1. **世界座標化だけの問題ではない。** カメラ座標と世界座標の全関節対距離の差は最大約1.5e-6m。
   したがって問題の手首間隔・膝角は世界座標化する前から同じ。
2. **77→24変換で位置を加工した問題ではない。** 保存された SOMA77 に現行変換を適用すると
   `gx_joints.npy` と完全一致。ただし名前の対応が解剖学的に同等か、公式assetとの照合は別途必要。
3. **Three.jsだけの問題ではない。** GEM-X自身のカメラ内メッシュにも身体配置のずれが見える。
   メッシュの画像重ね合わせは投影・画角にも依存するため、それだけで3D誤差を定量確定はしない。
4. **体型のフレーム間変動が主因とは考えにくい。** 保存された identity/scale パラメータは
   全フレームで同じ（先頭末尾差0）。単に体型を時間平均する修正では今回の腕の問題は直らない。
5. **足固定は別の混入要因。** 表示JSONは anchored=true で、骨盤相対の生座標と最大約11.4cm違う。
   今回の表はこの影響を除いた生NPYから計算。手首距離や肘角の大きな差は足固定では説明できない。

## 実装上の改善候補

### A. 骨格復元を公式経路に統一する

現行 `backend/reconstruct_gemx.py` は `from soma import SomaLayer` を使い、
`scale_params` を「そのまま／先頭をglobal_scaleに分離／先頭を捨てる」の順で試して、
例外が出ない解釈を採用している。実行成功は意味的な正しさを保証しない。

調査時の上流mainでは、デモが `gem.utils.soma_utils.soma_layer.SomaLayer` を使い、
ラッパーがglobal_scaleを分離、メートル単位を明示し、`repose_to_bind_pose=False`で人体を生成する。
実行環境で固定している3299255の該当コードはこの調査環境では取得できなかったため、
mainとの同一性や差による数値影響は未確認。

まず固定版の公式デモと同じ経路から関節を取り、保存済みパラメータで現在の出力と比較する。
これには画像モデルの再推論は原理的に不要。GPU Volumeのdebug予測も利用候補。
この修正で全問題が直るとは言わない。公式メッシュにもずれがあるため、本体の誤差は別途評価する。

### B. 2D入力を少量だけ人手修正し、改善余地を測る

f22,109,117,118,127,150前後の肩・肘・手首・股関節・膝を画像上で確認する。
重なり・左右取り違え・ブレ・関節定義を記録し、SOMA77に対応した位置を修正する。
見えない関節を自信のある観測として埋めず、欠損・不確かさを渡す。

上流デモは2Dの `kp2d` とSAM3D由来の `pose_tokens` 等を使う。
2Dだけ修正してどの程度3Dが改善するかをA/B比較し、2D検出器の改良が有効か判断する。
2D以外の特徴にも依存するので、2Dが正しければ必ず正しい3Dになるわけではない。
入力の変更時には人物検出/2D/特徴キャッシュを更新する。ファイル名だけの再利用を避け、
映像ハッシュ・前処理・モデル版をキーにする。

### C. GEM-Xを初期値にして、ゴルフの制約付き姿勢最適化を行う

推定されたSOMAの関節回転・ルート姿勢を最適化変数とする。
体型・骨長は原則固定し、フレームごとの関節座標を自由に動かさない。

- **再投影**：較正したカメラを通した3D関節が、信頼できる画像上の点と一致する。
- **グリップ**：両手で保持している区間だけ、両手の接触位置が同じクラブのグリップ上にある。
  手首中心は接触点ではない。最初は人手指定のクラブ軸・グリップ点を使ってもよい。
  手首同士を0距離にする、固定cmにする、手首だけを引き寄せる実装は避ける。
- **骨格**：順運動学/IKで骨長と関節可動範囲を維持する。
- **時間**：姿勢の不連続を抑える。ただしインパクトの速度ピークを消す過剰な平滑化を避ける。
- **接地**：根拠がある足・区間だけに適用。踵が上がる、軸足が回る、足を踏み替える動作を許す。
- **元推定への弱い拘束**：画像から不明な奥行きが無制限に変形しないようにする。

固定比率でSAMの腕とGEMの胴体をつなぐより、共通骨格・座標・関節定義に合わせて
複数推定を信頼度付きの初期値/拘束として使う。2つの不一致を平均するだけで真値にはならない。
この最適化は提案であり、現時点で本素材に実装・検証したものではない。

### D. それでも不足する場合

短い検証サイクルで、別の人・別の日の動画でも改善するか評価する。
許容誤差は用途・指標ごとに指導者と決め、画像の再投影誤差と独立した3D/側面の参照を分ける。
姿勢最適化で不足する場合に、許諾されたゴルフ素材と教師信号で追加学習を検討する。
自己出力やGVHMR出力を無条件に教師にせず、誤差と利用条件を確認する。
前処理で直るもの・制約で直るもの・追加観測が必要なものを区別し、
全局面の精度が足りない場合は1台運用で提供する指標を限定するか、同期2台を選ぶ。

## 実験結果（2026-09-21、Codex の作業を引き継いで実施）

**A. 公式 SOMA 経路との一致 — ✅ 一致。** `backend/golf_capture.py` で公式ラッパー
（`gem.utils.soma_utils.soma_layer.SomaLayer`）から関節を出し直したところ、従来経路の
`gx_joints.npy` と**最大差 0.000cm** で完全一致した。従来の「scale_params の先頭を
global_scale として分離」は公式の解釈と同じだった。`core/gemx.py` への差し替えは安全。
腕の崩れは復元経路の誤りではなく、モデルの出力そのもの。

**C. 再投影＋骨長固定の最適化 — ✗ 3D は悪化。** `tools/refine_golf.py`
（2D 入力は GEM-X 同梱の ViTPose、内部パラメータは既定の推定値）:

| | GEM-X | 補正後 |
|---|---:|---:|
| 再投影の中央値（補正に使わないフレーム） | 29.6 px | **6.6 px** |
| 両手首の距離 SD（〜インパクト） | 7.1 cm | **11.4 cm** |
| 両手首の距離 25cm 超のフレーム | 39 | 40 |
| リード膝 インパクト | 148.9° | **112.4°**（GVHMR 148.8°） |
| 最大の移動量 | — | 45 cm |

画像には合ったが、**奥行きを動かして辻褄を合わせた**。単眼では奥行きが
拘束されないので、再投影だけの目的関数はこうなる（docstring の警告どおり）。
グリップ拘束は未実装。実装しても手首を寄せるだけで肘・肩は戻らない、という
[011 §7d](011-commercial-architecture.md) の懸念は変わらない。

**結論の更新:** この再投影補正は不採用。「後処理全般で直せない」「SAMを横から撮れば
解決する」とまでは、この実験から結論できない。追加調査でViTPoseへのRGB/BGR入力の
不整合と、色順変更によるトップ付近の2D検出の改善を確認した（[016](016-golf-refinement-rejection.md)）。
まず入力を修正してGEM-Xを再評価し、床・カメラ・接触の検証を分ける。
`production_validated: false`、`adoption_status: rejected` として実験記録を残す。
確認画面: `web/golf-review.html?run=golf_accuracy`。

## 次の最小実験

1. 公式SOMA経路から再出力し、生データと一致するかを確認。
2. トップ・インパクト前後の短区間で、2D入力修正あり/なしを比較。
3. 同区間でグリップ＋骨長＋再投影による最適化あり/なしを比較。
4. 別クリップで再現。手首間隔だけ改善して、肘・肩・膝や再投影が悪化していないかを見る。
