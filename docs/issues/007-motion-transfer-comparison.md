## 背景: なぜプロ比較をやめたのか、そして何が変わったのか

プロとの比較は「差が必ずしも欠点ではない」「体格が違えば同じ関節角度は再現できない」
という理由で後回しにしていた（[REDESIGN.md](../../REDESIGN.md) P5）。

**[005](005-avatar-retargeting.md) のリターゲットが、この問題の解になる。**
アバター再生は遊びとして作ったが、実際には**体格差を吸収する技術**そのものだった。

## 中心にある考え方: 変数を1つに絞る

そのまま並べると、**2つのものが同時に違う**。

```
あなたの体 × あなたの動き   vs   お手本の体 × お手本の動き
        ↑ 体が違う                    ↑ 動きも違う
```

これでは「肘の角度が19°違う」と出ても、技術の差か腕の長さの差か**区別できない**。

転送すると、変わるものが1つだけになる。

```
あなたの体 × あなたの動き   vs   あなたの体 × お手本の動き
        ↑ 同じ                        ↑ 動きだけが違う
```

**見えている差はすべて技術の差**になる。体格という言い訳が消える。

つまり「転送 **か** 比較 **か**」ではなく、**転送して初めて比較が意味を持つ**。

## 技術的に安い理由

1. **SMPL は最初から体型と動きを分離している。**
   復元結果の `betas (F,10)`（体型）と `body_pose (F,63)`（動き）は独立なので、
   「お手本の `body_pose` ＋ 自分の `betas`」を組み合わせるだけで成立する。
   近似も変換も不要（モデルがそう設計されている）。

2. **もっと安い道: アバターは既に中立な体である。**
   [005](005-avatar-retargeting.md) の VRM アバターは体型が固定なので、
   **そこに2つの動きを流すだけで体格差はゼロ**になる。既存のリターゲットを
   2回呼ぶだけで済む。

3. **フェーズ検出が既にある。**
   沈み込み・打点を検出済みなので、スイングの速さが違っても
   「同じ局面同士」で並べられる。

## どの体に揃えるか（どれでもよい）

大事なのは「両方を同じ体で見る」ことだけ。

| 揃える先 | 見え方 | 実装 |
|---|---|---|
| **アバターの体** | 中立な第三の体 | **最も安い**（既存のまま） |
| **自分の体** | 「自分がこう動いたらこう見える」＝真似しやすい | 中（SMPLメッシュか骨格の描画が要る） |
| お手本の体 | 「自分の動きをお手本の体でやると」 | 中 |

## お手本の入手（プロでなくてよい）

**権利問題を回避でき、かつ実用的な選択肢がある。**

| 素材 | 権利 | 実用性 |
|---|---|---|
| **自分の「良かった1本 vs 悪かった1本」** | 問題なし | **素材ゼロで今すぐ試せる**。体格差もそもそもゼロ |
| **コーチ・上手い練習仲間** | 撮影の同意だけ | 体格や年齢が近く、**真似できる可能性が高い** |
| プロの公開映像 | 要確認 | 体格が離れがち。最後でよい |

「フェデラーの動き」より「そのコーチの動き」の方が到達可能な目標になりうる。

## 正直な限界

**幾何学的にどう見えるかは出せるが、それがあなたに可能かは別問題。**

- 肩の外旋可動域が足りなければ、その角度は物理的に出せない
- 手足の長さが違えば慣性が違うので、同じタイミングが最適とは限らない
- つまり「**目標の形**」は示せても「**あなたに到達可能**」の保証はない

提示は「これがお手本の形です」に留め、「こうすべきです」と断定しない
（[analysis](../../analysis/README.md) の Tier 分けと同じ姿勢）。

## 作業計画

### フェーズ A: 同じアバターで2つの動きを並べる（最も安い・まずここ）
- [ ] 参照モーション（`pose`）を保存・読み込みする仕組み
- [ ] 既存のリターゲットを2回呼び、アバター2体を並べて表示
- [ ] 素材は「自分の良い1本 vs 悪い1本」で開始（追加撮影が要らない）

### フェーズ B: 重ねて差を見せる
- [ ] ゴースト表示（半透明で自分に重ねる）
- [ ] ズレの大きい関節を強調

### フェーズ C: 時間を揃える
- [ ] 沈み込み・打点を基準にフェーズで整列（速さが違っても同じ局面を比較）
- [ ] 必要なら DTW

### フェーズ D: 差を数値にする
- [ ] 同じ体に揃えた状態での関節角の差分
- [ ] 体格差が消えているので、**打点の高さも初めて比較可能になる**

## 受け入れ条件

- 2つの動きが**同じ体**で並んで見える（体格差が視覚的に排除されている）
- 「自分の良い1本 vs 悪い1本」が追加素材なしで比較できる
- スイングの速さが違っても同じ局面で比較できる
- 差分を「目標の形」として提示し、到達可能性を断定しない

## リスク / 未解決

- **可動域の壁**。お手本の角度が自分の体で出せない場合の扱いが未定
  （将来は可動域の推定と組み合わせたい）
- お手本が1本だけだと、その人の「たまたまの1本」に引きずられる
- 自分の良い/悪いを判定する基準が今はない
  （[006](006-racket-tracking.md) のヘッド速度や打球音での質判定があると自動化できる）

## スコープ外

- 可動域・柔軟性の推定
- 「こう動けば良くなる」の自動生成（それは別テーマ）
- 複数のお手本の統計化（平均的なプロ像の構築）
