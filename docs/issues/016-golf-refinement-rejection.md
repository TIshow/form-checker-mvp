# ゴルフ補正の不採用と、2D入力・奥行き・床表示の追加診断

Status: Color fix verified by re-inference（トップは直った。フィニッシュの遮蔽と足は別問題）
日付: 2026-09-21

## 判断

ユーザーの実映像との照合を受け、015の再投影補正は**不採用**。
骨長を保ち、同じ動画内の保留フレームで2D検出へのずれが29.6→6.6pxに減っても、
正しい3Dを復元したことにはならない。保留フレームの入力も同じ検出器であり、
独立した正解や別動画での汎化評価ではない。

本番への自動組み込みは行っていない。比較画面・結果JSONに不採用を明示し、
再実行は `tools/refine_golf.py --experimental` を必要とする診断用途に限定した。
表示の足固定と計測の分離、公式SOMA経路の利用はこの補正とは独立して維持する。

## 各表示が異なる理由

| 表示 | 実際のデータ | 含む誤差 |
|---|---|---|
| 元の3Dを再投影（旧「補正前」） | GEM-Xのカメラ座標をKで画像に投影 | 3D姿勢・推定カメラ・奥行きの誤差 |
| 画像からの2D検出 | ViTPoseが画像から検出した関節 | 遮蔽、ブレ、左右取り違え、前処理の誤り |
| GEM-X・公式経路 | 同じGEM-X姿勢の世界座標を別視点で表示 | 元の3D誤差、世界の上向き、表示床の影響 |
| 不採用の補正 | 2D検出への一致を優先して変形した3D | 2D検出の誤りを取り込み、奥行き・曲がり方が悪化 |

「補正前」と「2D検出」は同じ推定を別の色で表示したものではない。
添付画像もf100、f102、f111と異なるため、同一フレームを固定して切り替える。
確認画面にフレーム番号の直接入力を追加した。

## 1. 入力の色順に具体的な不整合がある

固定版 `3299255` のコードを追うと:

1. `read_video_np` はRGB配列を返す。
2. 公式デモと今回の `capture` はその配列をViTPoseへ渡していた。
3. `vitpose_extractor.get_batch` はBGR入力を想定し、`crop[..., ::-1]` で反転する。
4. その結果、正規化してネットワークへ渡す色順がBGRになる。

これはコード上で確認できる不整合。精度への影響は別途A/Bで確認した。
同じ172フレーム、同じ検出箱、同じ重みを使い、ViTPoseの入力だけBGRへ変換して
内部の反転後にRGBになるようにした。SAMや検出器の入力を一律反転してはいけない。

| フレーム | 関節 | 既存2Dの位置(px)・スコア | 色順修正後の位置(px)・スコア |
|---|---|---|---|
| 109 | 右手首 | (525, 855), 0.28 | (415, 645), 0.81 |
| 111 | 右手首 | (547, 824), 0.35 | (410, 650), 0.79 |
| 150 | 左手首 | (604, 880), 0.66 | (594, 870), 0.38 |

f109/111では、胴体付近の誤検出から実際の両手付近に近づいたことを画像で確認。
f100/102の右手首、f150の左手首などの誤検出は残る。スコアは確率ではなく、
上昇だけで正確さを保証できない。正解ラベルによる全フレームの精度評価は未実施。

結果: `output_golf_color_ab/evidence_color.npz`, `audit.json`, `color_comparison.png`。
比較画面に「色順修正後の2D検出（別実験）」を追加。左右の3Dは旧入力のままで、
このA/BではGEM-X本体を再推論していない。

## 2. 補正の制約が足りず、間違った2Dにも追従した

補正には骨長固定・元姿勢への弱い拘束・補正量の時系列拘束を入れたが、
SOMAの関節回転と解剖学的可動域、クラブを握る接触、較正された床への接地を
拘束していない。カメラKも既定値で、体幹の姿勢を保ったまま手足を動かす構成だった。
この条件では、観測・カメラの誤差を奥行きや膝の過大な屈曲で吸収できてしまう。

さらにスコア閾値0.3で、f102右手首0.33、f111右手首0.35などの誤検出を採用。
f109右手首自体は閾値未満でも、隣接フレームの誤検出は時系列項を通して影響する。

同一フレームでの結果（GVHMRを正解にして計算していない）:

| f109 / 3.63秒 | 元のGEM-X | 不採用の補正 |
|---|---:|---:|
| 手首間隔 | 33.0cm | 51.6cm |
| 左膝角（180°が伸展） | 149.2° | 94.7° |
| 左右の足部最低関節点の高さ差 | 13.8cm | 23.4cm |

全関節中の最大移動量は45.2cm。記録は `output_golf_refined_v1/rejection_audit.json`。
これらは推定形状の差であり、実際の関節角や足裏の高さの測定値ではない。

## 3. 足の浮きには3D推定と表示床の両方がある

`web/skeleton.js:toDisplay` は、全フレームの足首・つま先の最低高さの中央値を
表示床にする。撮影場所の床平面を較正したものではない。各パネルでその基準を
別々に算出するため、床に対する上下位置だけで補正を比較するのも不十分。

ただし、表示床だけが原因ではない。元のGEM-Xでもf102の左右足部最低点に9.1cm、
f111に12.6cmの高さ差があり、これは全身を上下に動かしても消えない。
足首・つま先の関節中心は足裏と異なるので、この数字を実際の浮き量とは呼ばない。
世界の鉛直・床平面・足の回転・身体推定のどれが誤っているかは独立した観測が必要。

また公式SOMA経路と旧出力の差は最大約1e-6m。公式経路への変更だけでこの問題は直らない。
カメラ座標と世界座標は同じ形状の剛体変換であり、違う視点から見ると奥行き誤差が露出する。

## 修正する順序と採用条件

1. **入力監査を先に完了する。** ViTPoseの色順を明示して修正し、GEM-Xへ渡す2Dを再取得。
   bbox・座標・回転メタデータ・フレーム時刻を保持。色順設定もキャッシュキーへ入れる。
   既存GEM-Xのキャッシュをそのまま再利用しない。
2. **少数の人手確認点で2Dを評価する。** アドレス、テイクバック、トップ、インパクト、
   フィニッシュの手首・肘・膝・足部を可視/不可視付きで記録。見えない点を正解として埋めない。
   修正した2Dを使うGEM-X再推論と、元の推論を同一フレームで比較する。
3. **カメラと姿勢を分けて検証する。** Kは現在fx=fy=1920、主点(540,960)の推定値。
   内部パラメータ・歪み・三脚の姿勢・床を較正する。ゴルフのアドレスを直立とみなして
   前傾を打ち消さない。カメラや体格の誤差を膝の屈曲で埋め合わせない。
4. **必要なら人体モデル上で制約付き最適化を再設計する。** 関節回転・可動域を使い、
   目視で確認した接触区間だけ足裏と床、手とクラブの接触を使う。踵上げ、軸足の回転、
   グリップを離す動作を許す。手首同士を0cmにしたり両足を常に床へ押し付けたりしない。
5. **奥行きが重要な指標には同期した別視点を用意する。** 可能なら較正したスマホ2台で
   正面＋側面を同時撮影し、対応点から3Dを検証する。別テイクの正面と側面は同じ3Dの教師にはならない。
   1台だけで提供する場合は、不確実な指標を断定せず、測定可能な範囲を限定する。

採用は、独立した2D確認点・側面/複数視点の3D参照・接地・時系列・ゴルフの指標を
併せて評価して決める。再投影誤差だけを合格条件にしない。
この結果からSAM/GEM-Xのいずれかを全面採用したり、全ての後処理が無効と結論したりしない。

## 実験結果：色順を直して GEM-X を再推論した（2026-09-21、Claude）

上の §1 は 2D 検出の A/B までだった。`backend/reconstruct_gemx.py` に
`--vitpose-rgb`（既定 on）を足し、コンテナ内で `get_batch` の反転 1 行だけを
外して、同じ 172 フレーム（SHA `e318b573…`）を GEM-X 本体まで通し直した。
出力: `output_golf_gemx_rgb/`（`provenance.json` に `vitpose_input: rgb`）。
確認画面: `web/clip.html?clip=golf_gemx_rgb`（GEM-X のメッシュと 2D 検出の
オーバーレイも並ぶ）。

**再確認した色の経路**（固定版 3299255）: YOLOX は RGB→BGR に直してから渡す
（`yolox_detector.py:481`）、SAM 3D Body は RGB のまま渡す。ViTPose だけが
二重反転で BGR を見ていた。壊れていたのは 2D 関節の枝だけ。

| 両手首の距離 | 旧（BGR） | 新（RGB） | GVHMR（参照のみ） |
|---|---:|---:|---:|
| トップ f108 | 34cm | 21cm | 16cm |
| f104〜112 | 30〜34cm | 21〜24cm | 16cm |
| インパクト f117 | 18cm | 14cm | 18cm |
| スイング区間の SD（`grip_spread_sd_cm`） | 7.1cm | **4.5cm** | 4.6cm |
| フィニッシュ f132〜144 | 75〜78cm | 66〜74cm | 10〜16cm |

| その他 | 旧 | 新 | GVHMR |
|---|---:|---:|---:|
| インパクトのリード膝 | 148.9° | 147.8° | 148.8° |
| 左右の足の最低点の高さ差 最大 / f111 | 16.7 / 12.6cm | 16.4 / 14.1cm | — |
| 錨の足の滑り（`anchor_feet` の slide_before） | 62cm | 65cm | — |
| 局面（takeaway/top/impact/finish） | 79/110/117/127 | 80/110/117/127 | 81/110/118/131 |

**分かったこと**

1. **トップで両手が胴体に飛んでいたのは、色順が原因だった。** 2D の右手首が
   f109 で (525,855)→(415,645)、スコア 0.28→0.81 に戻り、3D もそれに従った。
   スイング区間の両手首の SD は GVHMR と同じ水準になった。
2. **フィニッシュは直らない。** f128〜150 は腕が頭と胴体の後ろに隠れ、修正後も
   2D の手首スコアが 0.5 未満（37 フレーム）。GEM-X は見えない手首を
   頭の後ろに回した姿勢を出す（メッシュで確認。旧も新も同じ崩れ方）。
   これは遮蔽の問題で、正面（背面）1 台では情報が無い。GVHMR が 10〜15cm を
   保っているのは、SMPL の学習データの事前分布が効いているためで、
   見えているからではない。
3. **足は色順と無関係。** 滑り・左右の高さ差は変わらない。上の §3 のとおり、
   世界座標の鉛直と接地の推定の問題として別に扱う。

**判断**: `--vitpose-rgb` は既定 on にした（正しい入力で、悪化した指標が無い）。
GEM-X の評価は 011 §7d の「両手首 25±21cm」を **この結果で更新する**：
スイング区間では健全、フィニッシュと足元は未解決。SAM 3D Body を横から撮る
線は変わらないが、「GEM-X の腕はモデルの出力段階で崩れている」という
015 の私の結論は撤回する——半分は入力の色順だった。
