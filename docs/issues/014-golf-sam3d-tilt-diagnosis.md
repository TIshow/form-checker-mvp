# ゴルフの SAM 3D Body 前傾差：保存データによる診断と修正順

Status: Diagnosis / Proposal（2026-09-20。推定器・製品コードの修正は未実施）

## 結論

同一フレームでも SAM 側の全身・体幹の傾きは大きい。ただし、これは単一の「モデル精度差」ではない。
未較正のカメラ座標と重力基準の世界座標を比較していること、単眼の奥行き推定、
人体の関節定義の違い、足の固定処理による変形が混在する。

最初に較正・比較条件・後処理を直し、その後に SAM 本体の限界を評価する。
本動画の実際のカメラ俯角や真の前傾角は未測定。GVHMR は比較対象であり真値ではない。
「SAM が悪い」「カメラが15°傾いている」「全身を回せば精度が直る」のいずれも現段階では断定できない。

## 同一フレームでの差

以下は生の NPY から計算した「骨盤→首」と各経路の上方向との3D角度。
SAM の上はカメラの -Y、GVHMR の上は世界の +Y。現状のアプリの体幹角定義に合わせた比較であり、
同じ重力軸による正確な身体前傾角の比較ではない。また側屈も含む傾きの大きさである。

| フレーム | 時刻 | GVHMR | SAM（未較正） | SAM（診断用の固定回転後） |
|---|---:|---:|---:|---:|
| 0 | 0.00 s | 15.5° | 34.2° | 19.5° |
| 22 | 0.73 s | 14.2° | 33.5° | 18.9° |
| 82 | 2.73 s | 13.3° | 27.0° | 13.9° |
| 109 | 3.63 s | 20.6° | 24.1° | 9.6° |
| 118 | 3.93 s | 16.5° | 29.0° | 18.7° |

診断用固定回転：骨盤相対の股関節・膝・足首・肩・肘・手首の12点を用い、
f0〜59 の SAM と GVHMR の差を最小にする回転を SVD/Kabsch で求め、全172フレームに同じ回転を適用した。
鏡映、拡縮、フレームごとの回転は使っていない。回転の det=+1 と直交性を確認。
この対応付けで上下方向の差は約15.2°。カメラの実測俯角ではなく、モデル間の姿勢バイアスも含む。

アドレス付近の角度差は縮む一方、f109 ではむしろ差が拡大する。
回転合わせ後にも12点の平均距離差は合わせた区間で8.2cm、残り区間で10.3cm残る。
これらは人体定義・体格差を含むモデル間不一致であり、精度指標 MPJPE の実測真値との誤差ではない。
GVHMR に合わせた回転を商用の補正・較正値として採用しない。

また f22 の生の膝角（180°が伸展）は、左 GV155.4°/SAM162.8°、右 GV154.4°/SAM165.2°。
関節角は全身の剛体回転で変わらない。したがって全身の向きだけでは説明できない差もある。

## 確認できた実装上の要因

### 1. カメラの上を重力の上として使っている（最優先）

- `backend/reconstruct.py` は `smpl_params_global` から関節を復元する。
- `backend/reconstruct_sam3d.py` は `pred_keypoints_3d + pred_cam_t` のカメラ座標を保存する。
- `core/kinematics.py::detect_up_axis` は頭と足首の平均方向から最大成分の軸を選ぶだけ。
  一般の3D重力ベクトルを推定したり、カメラの pitch/roll を補正したりしない。
- `web/skeleton.js::toDisplay` は軸・符号の置換、腰方向を使った yaw、床高の平行移動。
  これはカメラ姿勢の較正ではない。
- 保存した golf JSON は `coords=camera` / `up_axis=[1,-1]`。
  NPY と JSON の体幹方向差は最大約0.012°（丸め程度）で、体幹方向の較正は実質入っていない。

固定撮影でもカメラの角度は未知のまま。三脚だけではこの問題は解消しない。
一方、この観察だけでは「実際にカメラが傾いている分」と「モデルが体を傾けた分」は分離できない。

### 2. カメラ内部パラメータを与えていない（影響量は未検証）

`SAM3DBodyEstimator(..., fov_estimator=None)` で、`process_one_image` に `cam_int` も渡していない。
調査時の上流 main は、この場合 `fx=fy=sqrt(W²+H²)`、主点を画像中央とする既定値を使う。
実際の焦点距離・クロップ・歪みとのずれが、奥行きや姿勢推定に影響する可能性がある。
これは外部姿勢（重力・俯角）とは別の較正であり、FOV推定だけで全身の傾きが消える保証はない。
Modal は GEM-X の固定コミット配下の submodule を使っているため、実行環境の該当ソースも照合すること。

### 3. 元動画は正面撮影で、前後の傾きが奥行き方向にある

3Dビューを横に回しても、横から実際に撮った情報は増えない。
正面の見え方に合う奥行き配置が複数あり、SAM は画像と学習した事前分布から推定する。
GVHMR は動画の時系列と重力にそろえる設計を使うため、SAM のフレーム独立推定とは条件が違う。
この例で GVHMR が自然に見えることは妥当な観察だが、どちらの前傾角が正しいかは横撮り等が必要。

### 4. MHR→SMPL24 は同一の関節定義ではない

`core/convert.py::mhr70_to_smpl24` は骨盤を左右股関節の中点、脊椎3点を骨盤→首の直線補間、
頭を耳の中点で作る。GVHMR の SMPL 関節回帰と位置・意味が完全には一致しない。
特に「SAM の背骨がまっすぐ」は補間方式の影響も受ける。
MHR70 の観測点リストにないことと、MHR 人体モデル自体に骨盤・脊椎がないことは別。
現行上流 estimator は `pred_joint_coords`、関節回転、`mhr_model_params` 等も返す。
ネイティブ骨格を保存し、対応する解剖学的定義で指標を作る方がよい。

### 5. 足の固定が関節形状を変えている（前傾とは別の実測問題）

`core/anchor.py::anchor_feet` は全身の並進だけでなく、留めた足首・つま先を個別移動させる。
保存された golf JSON と生の NPY を比較すると、左膝角が最大12.45°（f105）、
右膝角が最大10.06°（f112）変化。脛長も左最大+5.41cm（f109）、右最大-4.63cm（f107）変わっている。
体幹角はほぼ不変なので、今回の全身前傾の主因ではないが、膝などの精度評価に混入する。
「膝角への影響は1°未満」というコメントはこの動画の全区間には当てはまらない。

### 6. 現在の「前傾」は側屈との区別がない

`Kinematics.trunk_lean()` は骨盤→首と上ベクトルの角度の大きさ。
前屈/後屈の符号や側屈を分離していないため、スイング中の値を純粋な前傾角と解釈しない。
重力・身体の左右方向・前方向を定義し、矢状面と前額面への投影角を別々に計算する。

## Claude Code に渡す修正順

1. **比較と保存を先に整える。** 同じデコード済みフレームID/PTS、同じ人物、同じ縮尺・正投影の視点で比較。
   raw / calibrated / display を別成果物にし、座標系・上方向・K・外部回転・変換履歴・欠損フラグを保存する。
   SAM の2D点、カメラ並進、焦点距離、ネイティブ関節・姿勢・体型パラメータも保存。
   出力の version/commit/weights hash とクロップ・回転メタデータを記録。
2. **独立した重力較正を導入する。** 同じ撮影設定でのIMU姿勢、既知寸法の床マーカーと較正済みK、
   または背景の鉛直・床方向による幾何較正を使い、SAM のカメラ座標を世界座標に移す。
   マット四隅は平面性と実寸・対応・Kが確認できるときの候補。推定された足点だけで真の床法線を保証しない。
   カメラ方向の再現にも同じ変換を適用。固定カメラでのみ固定回転が成立する。
3. **直立較正は暫定オプションとして扱う。** `--level-from` は使えるが、実際に中立直立した区間を選ぶ。
   本素材のアドレスを鉛直扱いすると本来の前傾まで消える。片足荷重のフィニッシュも安易に使わない。
   推定バイアスを含む経験的補正で、別ポーズへの一般化や1〜2°の精度を保証しない。
4. **内部パラメータを検証する。** 実撮影モードでのカメラ較正が第一候補。難しければFOV推定とのA/B比較。
   回転・リサイズ・クロップ後の画素系にKを合わせる。固定画角ならKを動画全体で共有し、毎フレーム揺らさない。
   現行上流 `cam_int` は注釈と異なり `.to()` を呼ぶため Tensor の型・次元も実装に合わせる。
5. **足固定を計測から切り離す。** 生の関節で形状・角度を評価。必要なら接地制約付きの姿勢最適化/IKで
   骨長・再投影・接地を同時に拘束し、接地不明/非接地を許す。足首だけ動かして「精度改善」としない。
6. **残る姿勢差を評価する。** 正面・飛球線後方の同期2台を少数例で取得し、較正と同期誤差を含む参照を作る。
   商用の1台運用では測りたい動きが画像面に出る撮影方向を選ぶ。前傾なら飛球線後方を優先。
   2D再投影一致だけでは奥行き精度を証明しない。前傾/側屈、膝角、再現性、失敗率を分ける。
7. **必要な場合だけ時系列最適化を足す。** 人物の体型・骨長を時系列で共有し、2D再投影、姿勢の時間連続性、
   接地を重み付きで最適化する。高速スイングを消す過度の平滑化を避ける。
   一定の前傾バイアスは移動平均では直らない。

この順でも用途の許容誤差に達しなければ、SAM の継続改良、他の商用候補、2台入力を比較する。
SAM を商用候補に挙げたことは、GVHMR と同等の動画・重力・奥行き精度を確認したことではない。
X の2D追跡や骨格描画のデモも、未知の側面姿勢や世界座標の精度を保証する証拠にはならない。
